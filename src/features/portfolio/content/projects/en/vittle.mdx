## Problem

An existing meal-planning product on an aging stack — React class components on Meteor/Node 8 — had accumulated bugs, an ordering flow that no longer matched the client's requirements, and admin screens that hadn't kept up with the data model.

## Approach

Fixed existing bugs across the user site and admin, updated the UI to new mockups, reworked the ordering logic for the new requirements, and rebuilt the order-management and user-info pages. Shipped new admin features adapted to the changed data — all within the legacy class-component/Meteor codebase rather than a rewrite.

## Result

Delivered as part of a 3-person team, keeping a production meal-planning product moving forward without a full migration off its legacy stack.
